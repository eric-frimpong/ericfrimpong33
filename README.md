### 🌐 Lab 3 — Cisco Packet Tracer: Inter-Network Routing

```
┌──────────────────────────────────────────────────────────────────┐
│  TOOL          Cisco Packet Tracer (Network Simulation)          │
│  DEVICES       Cisco 2811 Router │ 2960-24TT Switches │ PC-PT    │
│  NETWORKS      192.168.1.0/24 (LAN 1) │ 192.168.2.0/24 (LAN 2)  │
│  FOCUS AREA    Inter-network routing, default gateways, IOS CLI  │
└──────────────────────────────────────────────────────────────────┘
```

**Objective:** Connect two isolated LAN segments through a Cisco router, configure router interfaces via IOS CLI, set default gateways on all end devices, and verify end-to-end connectivity across both subnets — demonstrating core CCNA-level routing fundamentals.

**Network Topology:**

```
  PC-01 (192.168.1.1)              PC-03 (192.168.2.1)
        \                                /
         \  Fa0/1             Fa0/1     /
    [Switch1 2960]           [Switch2 2960]
         |  Fa0/3             Fa0/3     |
         |                              |
         +--------[ Router R1 ]---------+
               Fa0/0         Fa0/1
           192.168.1.100   192.168.2.100
         |                              |
  PC-02 (192.168.1.2)              PC-04 (192.168.2.2)
```

**What I built & practiced:**

| Task | Description |
|---|---|
| 🏗️ **Topology Design** | Placed and cabled two PCs per switch, connected switches to a central Cisco 2811 router, replacing the original direct switch-to-switch link |
| 🖥️ **Static IP Assignment** | Manually configured IPv4 address, subnet mask, and default gateway on all four PCs across both subnets |
| 🔧 **Router IOS CLI Configuration** | Used `enable`, `conf t`, `interface`, `ip address`, and `no shutdown` commands to bring up both router interfaces with the correct IP addresses |
| 🔁 **Default Gateway Setup** | Set `192.168.1.100` as the gateway for Network 1 PCs and `192.168.2.100` for Network 2 PCs, enabling packets to leave their local subnet |
| 🧪 **Connectivity Verification** | Used `ping` from PC-01 to confirm same-subnet success (`192.168.1.2` ✅) and cross-subnet failure before routing was configured (`192.168.2.1` ❌), then verified full cross-network connectivity after router setup (✅) |
| 📋 **Troubleshooting** | Diagnosed "Request timed out" errors, traced them to missing default gateways and unconfigured router interfaces, and resolved each issue systematically |

**Router CLI Commands Used:**

```
Router> en
Router# conf t
Router(config)# hostname R1
R1(config)# int f0/0
R1(config-if)# ip add 192.168.1.100 255.255.255.0
R1(config-if)# no sh
R1(config-if)# int f0/1
R1(config-if)# ip add 192.168.2.100 255.255.255.0
R1(config-if)# no sh
```

**Key outcomes:**
- Gained hands-on experience with Cisco IOS CLI — navigating exec/config/interface modes confidently
- Understood why default gateways are required for inter-subnet communication and how routers use their routing table to forward packets
- Practiced the full troubleshooting loop: isolate with ping → identify missing config → apply fix → verify resolution
- Reinforced CCNA fundamentals: subnetting, Layer 3 routing, and the distinction between switch (Layer 2) and router (Layer 3) behavior
